# 《我们的故事》Phase 2 — 升级方案

> 调研日期：2026-07-29
> 目标：从"功能完整网页"升级为"商业级互动数字纪念作品"

---

## 一、当前项目评估

### 优势
- 零依赖单页面架构，稳定性好
- 模块化 JS 设计，易于扩展
- Canvas 粒子系统基础扎实
- 完整流程已跑通

### 短板
- 粒子效果较朴素（无尾迹/无3D/无光晕叠加）
- 场景切换生硬（直接显隐，无过渡动画）
- 照片墙为平面 2D 卡片
- 音乐与动画无联动
- 缺少触摸互动反馈
- 爱心动画为 2D 平面

## 二、GitHub 资源调研结果

### 2.1 粒子系统

| 项目 | Stars | License | 最近更新 | 推荐理由 |
|------|-------|---------|----------|----------|
| **tsparticles/tsparticles** | 8,934 | MIT | 2026-07 | 功能最全，但包体积大，建议只取部分模块 |
| **drawcall/Proton** | 2,476 | MIT | 2026-07 | 轻量级纯 JS 粒子引擎，适合 Canvas 项目 |
| **simeydotme/sparticles** | 281 | MPL-2.0 | 2026-07 | 超轻量高性能，适合移动端 |

**选择方案：Proton**
- 理由：轻量（≈30KB）、纯 Canvas、MIT 许可、维护活跃
- 用途：增强粒子尾迹、花瓣、光效
- 不选 tsParticles：功能重叠且体积过大（≈300KB+），移动端性能不可控

### 2.2 页面转场动画

| 项目 | Stars | License | 推荐理由 |
|------|-------|---------|----------|
| **greensock/GSAP** | 27,179 | 商业需授权 | 行业标准，但许可证需注意 |
| **codrops/PixelTransition** | 93 | MIT | 创意像素转场，可借鉴思路 |

**选择方案：不引入外部库，自建 transition.js**
- 理由：场景数量固定（8个），自定义 Canvas 渐变过渡效率更高
- 参考 GSAP 的 Timeline 思路，用 requestAnimationFrame 实现
- 零额外体积

### 2.3 3D 照片墙

| 项目 | Stars | License | 推荐理由 |
|------|-------|---------|----------|
| **three.js** | 105,000+ | MIT | 3D 标准库 |
| **3dphotogallery** | 1 | MIT | 简单 demo 可参考 |

**选择方案：引入 Three.js（精简版）**
- 仅用于照片墙模块，其他模块保持 Canvas 2D
- 通过 ES modules 仅引入核心 + OrbitControls
- 文件 `threeScene.js`

### 2.4 音频可视化

| 项目 | Stars | License | 推荐理由 |
|------|-------|----------|----------|
| **foobar404/wave.js** | 733 | MIT | 专门音频可视化库 |
| **kelvinau/circular-audio-wave** | 280 | MIT | 圆形波形 |

**选择方案：自建 audioVisualizer.js**
- 使用原生 Web Audio API + Canvas
- wave.js 功能过于通用，我们的场景需要定制（爱心跟随音乐跳动）
- 更可控、更轻量

### 2.5 手势/触摸交互

**选择方案：使用原生 touch 事件**
- 无需第三方库
- 已有的 easterEgg.js 已有 touch 事件基础

## 四、分模块升级详情

### 4.1 粒子系统升级（particle.js）

**目标**：Apple 官网级粒子效果

| 改进项 | 实现方式 | 优先级 |
|--------|----------|--------|
| 粒子尾迹 | 每个粒子存储最近 5 帧位置，绘制半透明轨迹 | P0 |
| 多层景深 | 分 3 层（远景/中景/近景），不同速度/大小/透明度 | P0 |
| 动态模糊 | 粒子移动时根据速度增加拖影长度 | P1 |
| 光晕叠加 | 粒子周围径向渐变光晕，叠加 blend mode | P0 |
| 粒子大小随机分布 | 对数分布替代均匀分布，产生更多小粒子 | P1 |

**参考资源**：Proton 的 emitter 设计模式

### 4.2 爱心动画升级（heart.js）

| 改进项 | 实现方式 | 优先级 |
|--------|----------|--------|
| 3D 旋转 | 引入 Z 轴旋转 + 透视投影 | P0 |
| 粒子发光 | 每个粒子带光晕 + 外部发光层 | P0 |
| 粒子流线 | 粒子沿爱心轮廓流动（位置随时间偏移） | P1 |
| 心跳脉冲波 | 已有，增强发光效果 | P0 |

### 4.3 场景过渡（transition.js）【新增】

实现 4 种过渡效果，按场景选择：

| 过渡类型 | 适用场景 | 效果 |
|----------|----------|------|
| 粒子消散 | 文字星海 → 爱心汇聚 | 粒子向四周散开，新场景粒子出现 |
| 径向模糊 | 爱心 → 时间轴 | 画面径向模糊扩散，卡片淡入 |
| 淡入淡出 | 照片墙 → MV | 画面渐暗，视频渐亮 |
| 花瓣飘落 | MV → 最终结尾 | 花瓣粒子飘落，文字渐显 |

实现方式：使用 Canvas 离屏渲染，叠加过渡帧。

### 4.4 3D 照片墙（threeScene.js）【新增】

**不替换**现有的 2D photo egg，而是作为**增强模式**：
- 当照片彩蛋触发时，默认显示 2D 卡片（已有）
- 用户点击照片墙区域 → 切换 3D 模式
- 3D 模式：照片在 Z 轴空间排列，手势拖拽旋转

技术方案：
- Three.js CDN 按需加载（仅 145KB gzip）
- 或者使用 CSS 3D transforms（更轻量，但效果有限）
- **推荐 CSS 3D transforms**：零额外依赖，效果足够

### 4.5 音频可视化（audioVisualizer.js）【新增】

连接 Web Audio API 的 AnalyserNode：

| 可视化类型 | 应用场景 | 效果 |
|------------|----------|------|
| 粒子跟随跳动 | 文字星海漂浮时 | 粒子大小/颜色随音乐频率变化 |
| 爱心脉冲 | 爱心展示时 | 爱心呼吸幅度与音乐 BPM 同步 |
| 光环波纹 | MV 播放时 | 视频周围光环随音乐波动 |
| 花瓣飘落 | 最终结尾 | 花瓣飘落速度/数量随音乐波动 |

### 4.6 MV 花海效果（video.js 增强）

原有流程：
```
黑屏 → "有一段旋律" → 视频播放
```

升级流程：
```
黑屏 → "有一段旋律" → 粒子散开动画（1.5s） 
→ 花瓣粒子从画面外飘入（1.5s） 
→ 视频淡入播放（音乐同步） 
→ 视频结束 → 花瓣粒子飘散 
→ 回归星空
```

### 4.7 触摸交互增强（easterEgg.js + main.js）

| 交互 | 效果 | 实现 |
|------|------|------|
| 点击爱心 | 粒子爆炸 + 涟漪扩散 | touch 事件 + 粒子 burst |
| 滑动 | 照片墙滑动切换 | touchmove 坐标计算 |
| 长按 | 光晕扩散 + 震动 | 已有，增强视觉反馈 |
| 双指缩放 | 3D 照片墙 zoom | 手势识别 |

## 七、实施决策总结

```
采纳:
├── Proton (借鉴 emitter 模式, 不自建粒子引擎)
├── GSAP (参考动画理念, 不自建 transition engine)
├── Three.js (仅照片墙, 按需加载)
└── 原生 Web Audio API (自建 visualizer)

不采纳:
├── tsParticles (体积过大, 功能重叠)
├── wave.js (过于通用, 定制成本高)
├── 其他第三方库 (零依赖原则)
└── 完整 GSAP (商业许可复杂)
```
